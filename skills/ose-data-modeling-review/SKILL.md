# OSE 数据建模与评审

仅适用于 `/Users/jty/develop/code/ose` 及其三个现有项目，不推广至其他项目。

## 流程

1. 遵循目标项目规则，识别本次改动涉及的表、查询、指标与调用方；项目有 CodeGraph 索引时优先使用它定位代码。
2. 阅读 [references/rules.md](references/rules.md)，按当前业务库或未来数仓选择适用规则，区分硬性要求与需要设计理由的事项。
3. 开发时融入原任务，评审时根据实际代码举证。默认只检查本次新增或修改影响的数据逻辑；仅在用户明确要求全面审计时扩大范围。可以读取必要的历史上下文，但不顺手整改无关旧代码或强制整表迁移。
4. 运行适当的本地检查。数据库访问遵循项目授权要求；未实际执行 SQL 或查看执行计划时明确说明，不能宣称数据库验证通过。

## 已确定边界

- 当前报表与业务共用 MySQL 服务，允许经现有后端受控查询，隔离分析负载是后续目标。
- 业务指标在后端统一计算，前端负责展示，不强制引入数仓或 dbt。
- 业务库与数仓分别规定字段；数仓不统一强制自增主键和四个管理字段。
- 示例只用 MySQL 语法，实际版本、引擎和迁移方式从项目核实。
- 技术选型和原手册建设时间表仅供参考。

## 输出

中文沟通；向用户提问时，缩写附完整英文与中文解释。

发现问题给出文件位置、规则编号、影响与最小建议，区分“必须修复”和“需要说明设计理由”。无发现时说明检查范围和验证限制，不虚构问题。

完成修改后说明文件、解决的问题、旧逻辑影响、验证结果及剩余风险。本技能不额外授予数据库操作、提交或发布权限，也不新增原任务之外的确认流程。
